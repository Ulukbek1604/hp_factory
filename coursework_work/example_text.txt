1. Техническое задание
1.1. Введение
В современных условиях производственного рынка эффективное управление ресурсами предприятия становится ключевым фактором для успеха бизнеса. Производственные предприятия сталкиваются с необходимостью не только контролировать производственные процессы, но и вести финансовую дисциплину, управлять персоналом, контролировать закупки и продажи готовой продукции.
Информационная система учёта производства смартфонов Samsung разработана для решения задачи отсутствия единой цифровой системы управления. Без такой системы предприятие не могло эффективно отслеживать исполнение бюджета, управлять кредитными обязательствами, вести точный учёт сотрудников с выплатой заработной платы, контролировать закупки комплектующих и управлять ассортиментом продукции.
1.2. Цель работы
Цель работы — разработка и внедрение комплексного веб-приложения для производственного предприятия Samsung. Основная задача — создать инструменты, позволяющие авторизованным пользователям:
просматривать и управлять бюджетом предприятия;
регистрировать и отслеживать кредиты и погашение займов;
управлять сотрудниками, их должностями и выплатой заработной платы;
отслеживать закупки комплектующих и единицы измерения;
управлять ассортиментом готовой продукции, записями производства и продажами;
обрабатывать пользовательские заявки на производство и продажу.
1.3. Постановка задачи
В ходе анализа существующих процессов управления производственным предприятием Samsung были выявлены следующие проблемы:
Отсутствие единого инструмента учёта бюджета, затрудняющего отслеживание доходов и расходов.
Отсутствие системы управления кредитами, приводящего к трудностям контроля графика погашений и остатка задолженности.
Отсутствие автоматизированного управления персоналом, осложняющего расчёт заработной платы и отслеживание должностей.
Отсутствие системы отслеживания закупок комплектующих, затрудняющего контроль запасов и затрат.
Отсутствие цифрового инструмента управления ассортиментом готовой продукции, её производством и записями о продажах.
1.4. Цели и задачи создания системы
Назначение: разработка веб-приложения для управления производственным предприятием Samsung с целью предоставления менеджерам и бухгалтерам эффективных инструментов комплексного управления ресурсами.
Основные задачи:
упрощение процесса учёта бюджета и финансового планирования;
обеспечение быстрого доступа к информации о кредитах и статусе их погашения;
автоматизация управления персоналом, выплаты заработной платы и отслеживания должностей;
обеспечение прозрачного контроля закупок комплектующих и учёта единиц измерения;
эффективное управление ассортиментом готовой продукции, производством и продажами.
1.5. Функциональные требования
Создание и редактирование записей бюджета.
Просмотр истории бюджета с фильтрацией и сортировкой.
Регистрация кредитов и погашение активных кредитов (не более 3 одновременно).
Отслеживание статуса погашения кредитов.
Создание, редактирование и просмотр записей о сотрудниках.
Расчёт заработной платы и отслеживание должностей.
Регистрация закупок комплектующих и единиц измерения.
Управление ассортиментом готовой продукции (создание, редактирование, запись производства).
Регистрация и просмотр продаж готовой продукции.
Автоматическое обновление бюджета после закупок, продаж, кредитных операций и выплаты заработной платы.
Проверка наличия комплектующих перед производством продукции.
Пользовательские заявки на производство и продажу с автоматической обработкой.
Отображение последних операций на панели управления.
Формирование аналитических отчётов и графика изменения бюджета.
1.6. Требования к клиентской части
Клиент может использовать один из следующих веб-браузеров: Google Chrome, Mozilla Firefox, Yandex Browser и другие.
Для работы с системой пользователь должен пройти аутентификацию с действующим именем пользователя и паролем.
После входа доступ к конкретным функциям контролируется ролевыми разрешениями (Admin, Manager, User).
Сеанс поддерживается безопасно; интерфейс автоматически адаптируется к роли пользователя.
Интерфейс должен быть простым, понятным и удобным для ежедневной работы.
Главные страницы приложения должны быть доступны через боковую панель навигации.
Система должна отображать важную информацию — текущий бюджет и авторизованного пользователя — в видимой области интерфейса.
Клиентская часть должна поддерживать работу с формами, таблицами, кнопками и динамически отображаемыми данными.
Страницы должны поддерживать базовые операции: добавление, редактирование, удаление записей и просмотр истории операций.
Сообщения об ошибках должны отображаться в понятном для пользователя виде при нарушении бизнес-правил.

3. Хранимые процедуры и триггеры
3.1. Хранимая процедура sp_CheckBudget
Для проверки бюджета при закупке сырья была создана хранимая процедура sp_CheckBudget. Она получает сумму закупки и возвращает результат проверки: достаточно ли средств в бюджете предприятия.
Процедура
Параметры
Описание
sp_CheckBudget
@PurchaseSum FLOAT (вход) @IsSufficient INT (выход)
Проверяет, достаточно ли средств в бюджете для проведения закупки. Возвращает 0 — достаточно, 1 — недостаточно.
Код хранимой процедуры:
CREATE OR ALTER PROCEDURE sp_CheckBudget
    @PurchaseSum  FLOAT,
    @IsSufficient INT OUTPUT
AS
BEGIN
    SET NOCOUNT ON;
    DECLARE @CurrentBudget FLOAT;
    SELECT TOP 1 @CurrentBudget = BudgetAmount FROM Budget;
    IF @CurrentBudget IS NULL
        SET @CurrentBudget = 0;
    IF @CurrentBudget &gt;= @PurchaseSum
        SET @IsSufficient = 0;
    ELSE
        SET @IsSufficient = 1;
END;

4. Серверная часть
4.1. Технологии и инструменты
Серверная часть приложения разработана на языке Python с использованием фреймворка Django. Приложение следует архитектуре MVT (Model–View–Template). В качестве базы данных использован Microsoft SQL Server, подключение к которому осуществляется через mssql-django.
Используемые технологии:
Python 3.12 — язык программирования;
Django 5 — фреймворк для веб-разработки;
Microsoft SQL Server — система управления базами данных;
mssql-django — СУБД-адаптер для Django;
Bootstrap 5 — библиотека для стилизации пользовательского интерфейса;
Jinja2 / Django Templates — шаблонизатор для формирования HTML-страниц;
Font Awesome — библиотека иконок.
4.2. Структура проекта
Проект организован по стандартной структуре Django-приложения:
samsung/ — основное приложение (модели, представления, шаблоны);
templates/ — HTML-шаблоны страниц;
static/ — статические файлы (CSS, JS, изображения);
settings.py — конфигурация проекта и подключение к БД;
urls.py — маршрутизация URL-адресов.
4.3. Модели
Каждая таблица базы данных представлена соответствующей моделью Django. Связи между моделями реализованы через ForeignKey. Пример модели Production:
class Production(models.Model):
    productid   = models.ForeignKey(Finishedproducts,
                    on_delete=models.CASCADE, db_column='ProductId')
    quantity    = models.FloatField(db_column='Quantity')
    productiondate = models.DateField(db_column='ProductionDate')
    employeeid  = models.ForeignKey(Employees,
                    on_delete=models.CASCADE, db_column='EmployeeId')
    class Meta:
        db_table = 'Production'
4.4. 
Представления
 (Views)
Каждая бизнес-функция реализована в отдельном представлении Django. Декоратор @admin_required ограничивает доступ для неавторизованных пользователей. Пример представления для производства:
def production_list_view(request):
    productions = Production.objects.select_related(
        'productid','employeeid').order_by('-productiondate')
    products    = Finishedproducts.objects.all()
    employees   = Employees.objects.all()
    context = {'productions': productions,
               'products': products, 'employees': employees}
    return render(request, 'samsung/production.html', context)

4.6. Обработка исключений
Файл auth.py содержит декоратор @admin_required, который проверяет роль текущего пользователя и перенаправляет неавторизованных на страницу 403. Глобальная обработка ошибок 404 и 500 также настроена в settings.py.
5. Клиентская часть
5.1. Интерфейс пользователя
Пользовательский интерфейс реализован на основе Bootstrap 5 и кастомных CSS-стилей. Навигация осуществляется через боковую панель. Страницы поддерживают добавление, редактирование и удаление записей через модальные окна и формы.
5.2. Ролевая модель доступа
В системе реализовано три роли пользователей:
Admin — полный доступ ко всем разделам и операциям;
Manager — доступ к закупкам, производству и продажам;
User — доступ только к отправке заявок на производство и продажу.

10. Заключение
В результате выполнения курсового проекта была разработана информационная система учёта производства смартфонов Samsung. Система объединяет базу данных Microsoft SQL Server и веб-приложение Django. В проекте реализованы справочники, учёт закупок, производство продукции, продажа готовых смартфонов, учёт бюджета, зарплаты, кредитов, заявок пользователей и отчётности.
Разработанное приложение позволяет контролировать основные производственные и финансовые процессы предприятия. Использование транзакций, внешних ключей, хранимых процедур, триггеров и серверной валидации повышает надёжность обработки данных и уменьшает вероятность ошибок при выполнении операций.
В ходе работы над проектом были получены практические навыки проектирования реляционных баз данных, написания T-SQL процедур и триггеров, разработки Django-приложений по архитектуре MVT, а также интеграции Python-приложений с Microsoft SQL Server.
